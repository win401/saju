# 결 — 사주 리포트 포트폴리오 데모

Next.js App Router + TypeScript + **일반 CSS**. 모바일 화면 폭(최대 480px)으로 제작했고 PC에서는 가운데에 같은 화면이 표시됩니다. Tailwind, Sass, CSS-in-JS를 사용하지 않습니다.

## 시작하기

Node.js 22 이상과 npm을 권장합니다. 개발 당시 Node.js 24에서 검증했습니다.

```sh
npm ci
SAJU_PUBLIC_DEMO=1 npm run dev
```

http://127.0.0.1:4173 에서 확인합니다. 위 명령은 공개 무료 체험 모드로 실행합니다. 기본 규칙 기반 리포트와 사전 작성 상담 예시는 외부 계정이나 API 키 없이 동작합니다. 실시간 AI 연애 상담은 별도 서버 설정이 필요합니다. 개발 서버의 기본 주소는 위 주소로 고정되어 있습니다. Vercel에서는 신뢰할 수 있는 시스템 환경 변수의 배포 주소를 동출처 검사에 사용하며, 별도 도메인은 `.env.example`의 `APP_ORIGIN`으로 지정합니다. 공개 무료 체험과 AI 설정은 [배포 문서](../docs/DEPLOYMENT.md)를 참고하세요.

```sh
npm run test       # 달력, 입력 검증, 해설 분기, 임시 데이터 접근 테스트
npm run format     # 일반 CSS와 코드 정리
npm run typecheck
npm run test:e2e   # 로컬 모의 주문 모드의 테스트. 설치된 Google Chrome 사용
npm run build
npm start          # production 기본값은 상세 체험 차단; 공개 무료 체험은 별도 opt-in
```

기존 `test:e2e`는 `SAJU_PUBLIC_DEMO=0`인 개발 서버를 대상으로 합니다. 공개 체험 모드의 서버를 켜두었다면 종료한 뒤 실행하세요. 공개 체험 서버의 테스트는 `PUBLIC_DEMO_URL=http://127.0.0.1:4173 npm run test:e2e:public`로 별도 실행합니다. production으로 공개 데모를 실행할 때는 **빌드와 실행 모두** `SAJU_PUBLIC_DEMO=1`을 적용하고 `APP_ORIGIN`에 실제 서비스 origin을 지정합니다. 테스트 수와 배포 검증 결과는 [배포 기록](../docs/DEPLOYMENT.md)을 기준으로 합니다.

## 동작하는 범위

- 별명, 성별(여성·남성·다른 성별·밝히지 않음), 양력/한국 음력, 윤달, 출생시간 또는 시간 모름, 사주×MBTI 상품의 필수 유형 선택
- 한국 음력→양력 변환, 절기 기준 년주·월주, 일주·시주 계산
- 확인된 원국의 표면 오행 개수, 십성·지장간·월지 계절·육합/충에서 선택한 근거를 사용하는 관계 해설 초안
- 선택한 관심 장면을 도입 질문·상세 상황·이번 주 실천에 반영, 각 장의 근거 펼쳐보기
- 각 입력 화면에서 가상 프로필 샘플로 바로 체험. 샘플은 기존 저장 프로필을 덮어쓰지 않음
- 공개 데모: 무료 요약→전체 리포트 바로 열기→네 개 상세 장 탐색. 예정 가격·모의 결제 확인 모달 없이 이용
- 공개 데모를 끈 로컬 개발: 기존 예정 가격·0원 모의 주문 흐름을 별도 유지
- 입력 수정, 오류 복구, 데이터 지우기. 로컬 임시 리포트는 세션 소유권·만료 확인
- 기본 출생정보를 같은 브라우저에서 24시간 기억해 세 콘텐츠의 입력에 재사용. 저장 해제·삭제 지원. 이전 검증과 이번 변경의 검증 결과는 배포 기록에서 구분

**MBTI 검사는 제공하지 않습니다.** 사용자가 선택한 유형만 참고하며 미입력 시 추측하지 않습니다. 공식 검사 문항, 공식 리포트, 인증 로고를 사용하지 않습니다. 상표 표시·상품명은 출시 전 별도 검토 대상입니다.

## 계산 정책과 한계

- 현재 범위는 **양력 1990-01-01 이후, 한국 출생, 고정 KST(UTC+9)** 입니다. 과거 한국의 표준시·서머타임 이력을 잘못 적용하지 않도록 1990년 전 입력은 명시적으로 거절합니다.
- 음력 변환: MIT `korean-lunar-calendar`. 중국 음력과 한국 음력을 같은 달력으로 취급하지 않습니다. 음력 2월 30일은 존재할 수 있어 음력 입력에는 HTML 양력 날짜 선택기를 사용하지 않습니다.
- 절기: MIT `lunar-typescript`의 절입 순간을 사용합니다. 라이브러리의 UTC+8 절기 시각과 KST 입력의 한 시간 차이를 년주/월주 계산에 반영합니다.
- 일주: 한국 달력의 간지 일진. **자정(00:00)에 일주 변경**, 시주는 이 일간 기준으로 계산합니다. 야자시·조자시를 별도 학파 기준으로 바꾸는 옵션은 아직 없습니다.
- 출생지별 진태양시·경도 보정, 해외 시간대, 대운, 용신/신강 판단은 구현하지 않았습니다.
- 출생시간 미상은 시주를 생략합니다. 절기 변경일이면 하루 시작/끝의 년주·월주를 비교해 변하는 주는 미확정으로 반환합니다. 정오를 실제 출생시간처럼 보여주지 않습니다.
- 원국 표의 오행은 확인된 천간·지지의 단순 개수입니다. 별도로 십성·지장간·월지 계절을 계산하지만 오행 개수에 가중치로 합산하지 않습니다. 계절 전환 월지의 표시 기준, 육합/충 선택, 규칙·검수 상태는 [`관계 해석 엔진`](../docs/INTERPRETATION_ENGINE.md)에 기록합니다.
- 성별은 사용자 프로필 입력값으로 표시합니다. 현재 제공하는 사주 네 기둥과 해설에는 반영하지 않으며, 성별에 따라 달라지는 대운 계산은 아직 구현하지 않았습니다.
- 알려진 음력 변환 사례와 간지 기준일, 라이브러리 절기 경계 회귀 테스트가 있습니다. 국내 전문 만세력과 대규모 교차 검증을 완료한 상용 엔진은 아닙니다.

## 결제·리포트·데이터

기본 상세 해설은 **규칙 기반 해석**이며 외부 AI를 호출하지 않습니다. 별도의 AI 연애 상담은 OpenAI 연동을 구현했으며, 사전 작성 상담 예시는 실시간 AI 결과와 구분해 제공합니다. 실제 API 답변 품질·비용 검증은 배포 기록을 참고하세요. PG 결제, 실제 고객 청구, 이메일, DB, 로그인, 광고 추적은 연결하지 않았습니다.

해설은 상품별 `traditional-0.1.0` / `relationship-0.3.0` / `mbti-0.1.0`, 계산 특징은 `saju-facts-v1`로 버전을 기록합니다. 각 장은 `chart / mbti / focus` 근거를 구분하며 서버에서 계산한 내부 `audit`에 실제 적용 조건을 남깁니다. `audit`는 API 응답에 포함하지 않습니다. 로컬 임시 리포트의 규칙 버전이 바뀌면 재생성이 필요하고, 공개 체험은 요청마다 현재 규칙으로 계산합니다. 자동 테스트는 구현의 일관성 검사이며 명리 전문가의 문안 검수나 외부 만세력 교차 검증을 대신하지 않습니다.

`POST /api/reports`는 미리보기 2장만 반환하며, 상세 생성 문안 모듈을 클라이언트 번들에 넣지 않습니다. 공개 데모는 전체 리포트를 바로 열 수 있고, 공개 모드를 끈 로컬 개발만 예정 가격·0원 모의 주문 화면을 유지합니다. PG 테스트 결제나 실제 주문은 아닙니다.

| 실행 모드 | 전체 체험 경로 | 입력·리포트 처리 |
| --- | --- | --- |
| 로컬 개발, `SAJU_PUBLIC_DEMO` 꺼짐 | `/api/reports/:id/demo-checkout` | 프로세스 메모리에 세션당 1개, 최대 1시간 보관. 임의 세션 ID 쿠키로 접근 확인 |
| 공개 무료 체험, `SAJU_PUBLIC_DEMO=1` | `/api/demo/readings` | 전체보기 버튼으로 같은 입력을 다시 전송하고 재검증·재계산. DB·서버 Map·쿠키에 입력이나 리포트를 보관하지 않음 |
| production 기본값, 공개 체험 꺼짐 | 두 상세 체험 경로 차단 | 미리보기는 기존 임시 저장 방식. 실제 판매 준비가 끝난 상태는 아님 |

공개 무료 체험에는 구매 권한이나 결제 우회 개념이 없으며 모든 상세 내용이 무료입니다. 결과는 현재 화면의 메모리에만 남아 새로고침·페이지 닫기 시 초기화됩니다. 생성 및 전체 체험 요청 때 입력은 서버로 전송되어 계산됩니다. 공개 체험 서버는 요청 본문이나 리포트를 별도 저장·로그하지 않습니다. 로컬 모드의 임시 리포트는 서버 재시작 시 유실되며 입력 재생성/초기화 때 삭제합니다. 실제 판매에 필요한 영속 저장소·구매 인증은 아직 없습니다.

입력 화면의 **‘이 브라우저에 내 정보 24시간 기억하기’**는 기본 선택되어 있습니다. 무료 리포트 생성에 성공하면 허용한 공통 필드(별명·성별·생년월일·양력/음력·윤달·출생시간/시간 모름·출생지·MBTI)만 localStorage에 저장합니다. 같은 주소(origin)의 같은 기기·브라우저에서 세 콘텐츠를 이동하거나 새로고침하면 이 값으로 입력을 채웁니다. 선택한 상품·관심 장면, 리포트 결과, AI 질문·체험 코드·전송 동의는 저장하지 않습니다. 복원만으로 리포트나 유료 AI 요청을 자동 생성하지 않으며 사용자가 다시 제출합니다.

샘플 체험은 가상 프로필(2000-03-07 12:00, 별명 ‘샘플’, 여성, MBTI 콘텐츠에서는 INFP)을 사용하며 프로필 저장을 수행하지 않습니다. 기존에 저장된 실제 입력을 샘플로 덮어쓰지 않습니다.

저장 기간은 저장 시점부터 24시간입니다. 만료값은 복원하지 않고 콘텐츠 입력 화면을 다시 열 때 또는 해당 콘텐츠 화면을 사용 중일 때 삭제합니다. 브라우저가 닫혀 있는 동안에는 삭제 코드를 실행할 수 없어 콘텐츠 입력 화면을 다시 열 때 제거합니다. 저장 선택을 해제하거나 저장 정보 삭제·기존 초기화를 실행하면 저장된 프로필도 지웁니다. sessionStorage에는 출생정보를 저장하지 않으며, 이 기능은 서버 보관·로그인·기기 간 동기화가 아닙니다.

API 요청은 4KB 제한, 서버 입력 검증, 동출처 검사, no-store 응답을 적용했습니다. 운영 전에는 속도 제한, 악용 방지, 운영 관측, 인증, 실제 주문 권한 검증도 필요합니다.

## 선택 기능 — AI 연애 상담

연애 결과에는 API 키 없이 읽을 수 있는 **사전 작성 상담 예시**를 제공합니다. 예시는 사용자의 사주를 분석해 새로 생성한 답변이 아니며, 사용자에게 그 차이를 명시합니다. 실제 질문을 보내는 상담은 별도 흐름으로 구분하고 기존 서버 접근 코드 보호를 유지합니다.

`/readings/love`에서 출생정보를 입력한 뒤 결과 화면의 ‘여울의 상담실’ 패널을 사용합니다. 별도의 상담 페이지나 결제는 없습니다. `POST /api/ai/love`는 출생 입력, 현재 연애 상태, 8~500자 질문, 명시적인 AI 전송 동의를 받습니다. 사주 원국과 해석 단서는 서버가 다시 계산하며 브라우저가 만든 사주 근거를 신뢰하지 않습니다. OpenAI에는 계산된 사주 단서·편집 해석 예시·연애 상태·질문을 보냅니다. 원본 생년월일·출생시간·별명·성별을 별도 필드로 보내지 않지만, 질문에 사용자가 적은 개인정보는 질문과 함께 전달될 수 있습니다. 기본 리포트를 읽는 것만으로 AI 전송이 발생하지 않습니다. 새 질문은 이전 대화 없이 다시 동의받아 독립적으로 요청합니다.

기본 모델은 `gpt-6-sol`이며 Responses API의 구조화된 JSON 출력을 사용합니다. 출력 형식·분량·근거 ID를 서버에서 검증하지만 이것이 상담 내용의 명리 타당성이나 품질을 보증하지는 않습니다. 요청 제한은 45초, 자동 재시도 0회, 최대 출력 6,000토큰입니다. `store: false`를 사용해도 제공사의 보안·악용 방지 보관까지 없어지는 것은 아니며 Zero Data Retention을 의미하지 않습니다. [OpenAI 데이터 처리 안내](https://developers.openai.com/api/docs/guides/your-data)를 기준으로 실제 계정 설정을 확인해야 합니다.

활성화에는 `SAJU_AI_ENABLED=1`, 서버 전용 `OPENAI_API_KEY`가 필요합니다. production은 최소 16자의 `SAJU_AI_ACCESS_CODE`도 필수이며 화면의 체험 코드로 입력합니다. 이 코드는 OpenAI API 키가 아닙니다. 로컬에서는 체험 코드를 생략할 수 있으나 설정했다면 같은 길이 조건을 만족해야 합니다. `GET /api/ai/love`는 사용 가능 여부만 반환합니다. 키나 코드는 채팅·클라이언트 코드·Git에 넣지 말고 [배포 문서](../docs/DEPLOYMENT.md)의 서버 환경 변수 절차를 따릅니다.

비용 보호는 프로세스별 10분당 8회 시도·동시 2회 제한과 접근 코드입니다. 서버리스 전체 인스턴스를 합산한 한도나 월 비용 상한은 아닙니다. 로컬 키는 미설정이며 Vercel production에는 사용자가 키를 등록했습니다. 첫 실제 호출은 `quota_exceeded`로 종료됐으며 API 결제·한도 확인 후 답변 품질·비용·지연시간을 검증해야 합니다. 비활성 상태에서도 기본 규칙 기반 리포트는 이용할 수 있습니다.

## 다음 단계

1. 국내 만세력 기준과 경계 사례 교차 검증 및 계산 정책 최종 확정.

## 메인과 세 가지 상품

`/`는 상품 선택 메인입니다. `/readings/traditional`, `/readings/love`, `/readings/mbti`에서 각 콘텐츠를 시작합니다. `features/reading/catalog.ts`는 상품 표시와 목차, `features/reading/server/create-report.ts`는 상품별 생성 분기입니다. 공용 리더·로컬 임시 저장은 `features/reading`, 개별 해석은 `traditional/relationship/mbti`에 분리했습니다. 공개 무료 체험은 저장 모듈을 사용하지 않습니다. 입력 `theme` 기본값은 `traditional`입니다. MBTI 상품은 유형 필수이며 다른 상품은 유형을 서버에서 제거합니다. [콘텐츠 구조](../docs/CONTENT_ARCHITECTURE.md)를 참고하세요.

# 메인과 세 가지 콘텐츠

결정: 2026-09-26. 관계 질문 중심의 첫 콘텐츠를 기본 서비스로 쓰지 않고, **정통 사주를 첫 상품**으로 배치한다. 사용자가 확정한 나머지 두 콘텐츠는 연애 사주와 사주×MBTI다.

| 주소 | 내용 | 입력과 구분 |
| --- | --- | --- |
| `/` | 세 상품을 고르는 메인 | 정통 사주 강조, 상품별 실제 진입 링크 |
| `/readings/traditional` | 타고난 바탕, 오행, 십성, 일·재물, 대인관계, 종합 해석 | 출생정보만 해석에 사용, MBTI·관심 장면 제외 |
| `/readings/love` | 끌림, 표현, 갈등, 나에게 맞는 관계 | 출생정보와 선택한 연애 관심 장면, MBTI 제외 |
| `/readings/mbti` | 사주와 입력한 MBTI를 에너지·인식·판단·생활 리듬의 네 축으로 비교 | MBTI 선택 필수, 자체 검사와 유형 추정 없음 |

세 상품은 미리보기 2장과 상세 4장을 갖는다. 로컬에서는 0원 모의 주문으로, `SAJU_PUBLIC_DEMO=1` 공개 배포에서는 무료 체험 확인 후 상세를 읽는다. 두 방식 모두 실제 청구는 없다. 예정 가격은 운영 가격 확정이나 실제 결제 연결을 뜻하지 않는다.

## 코드 구조

- `web/src/features/home/`: 상품 선택 메인과 일반 CSS.
- `web/src/features/reading/`: 공용 입력·원국 표·장별 읽기·체험 UI, 상품 목차, 로컬 서버 임시 저장 및 생성 분기.
- `web/src/app/api/demo/readings/route.ts`: 공개 무료 체험의 입력 재검증·상세 재계산. 이전 요청의 저장 데이터나 쿠키를 사용하지 않음.
- `web/src/features/traditional/server/`: 정통 사주의 10일간·10십성 전용 문안과 종합 리포트.
- `web/src/features/relationship/server/`: 연애의 원국 단서 선택과 장면·대사 문안.
- `web/src/features/mbti/server/`: 직접 입력한 네 선호 축과 선택한 사주 단서를 비교하는 리포트.
- `web/src/lib/saju.ts`, `saju-analysis.ts`: 모든 상품이 공유하는 달력·원국·특징 계산.

제목만 바꾸어 같은 상세 내용을 내보내지 않는다. 정통과 연애는 별도 문안 데이터, MBTI는 별도 장 구성을 사용한다. 입력 검증에서 상품과 관련 없는 MBTI·관심 장면을 지운 뒤 생성한다. 잘못된 상품 주소는 404, 없는 상품 코드는 입력 오류다.

## 읽기 품질 기준

각 장은 `lead + sections + evidence`로 구성한다. 화면은 소제목, 설명, 가상 장면, 안내자의 말로 나누어 읽게 하고 `body`는 동일 본문을 한 번 합친 텍스트다. 근거는 접힌 영역에서 확인한다.

정통 사주의 기본 내용은 일간 이미지에서 시작하되, 실제 월간·지장간·관측 오행·계절·합충을 장별로 선택해 이어간다. 오행 개수가 많다는 이유만으로 신강·신약이나 재물 크기를 판정하지 않는다. 모르는 출생시간·경계 기둥을 추정해 메우지 않는다. 성별·별명·MBTI로 정통 해석을 바꾸지 않는다.

연애는 해석 → 상황 → 오해 → 대화의 흐름으로 확장한다. 마지막 조언은 관심 장면만으로 고정하지 않고 사주에서 선택한 단서를 함께 쓴다. 사주×MBTI는 두 체계를 합산해 새 성격 점수나 유형을 만들지 않는다.

## 현재 한계와 다음 순서

문안은 **규칙 기반 편집 초안**이다. 원국·십성의 계산과 서사의 타당성은 다른 검수 대상이다. 명리 전문가 검수, 전문 만세력 교차 검증, 독자 시범 읽기는 미완료다. LLM API도 연결하지 않았다. 대운·세운·용신·신강 판정이나 특정 사건의 미래 예측은 구현 범위가 아니다.

1. 정통 사주를 실제로 읽고 어떤 부분이 얕거나 반복되는지 먼저 수정한다.
2. 같은 일주·다른 월주, 시각 미상, 절기 경계 사례를 포함해 전문 검수를 진행한다.
3. 연애와 MBTI는 서로 다른 상품으로 읽히는지 확인하고 분량·시각·전환 흐름을 조정한다.
4. 검수된 입력과 해석 근거를 확보한 뒤 AI 서술과 실제 결제·저장을 연결한다.

로컬 개발은 서버 메모리에 세션당 1개, 최대 1시간 보관하며 다른 상품에서 새 결과를 만들면 이전 임시 결과를 교체한다. 공개 무료 체험은 요청마다 입력을 전송해 재계산하고 앱 DB·서버 Map·쿠키에 입력·결과를 보관하지 않는다. 현재 화면의 입력과 결과는 새로고침 시 초기화된다. 미리보기 API에 상세 장·전체 `audit`를 반환하지 않고, 공개 전체 체험 API에는 상세 장만 제공하며 내부 `audit`는 보내지 않는다. 모드별 설정과 API는 [배포 문서](DEPLOYMENT.md)를 참고한다.

# 관계 해석 엔진 V1

갱신: 2026-09-26 · 규칙 버전 `relationship-0.3.0` · 계산 특징 버전 `saju-facts-v1`

상태: **동작하는 규칙 기반 초안. 명리 전문가 검수 및 외부 만세력 교차 검증은 미완료.** 이 문서는 계산·규칙 선택의 재현성과 해석 문안의 타당성을 구분한다. LLM API·RAG·별도 학습 모델은 아직 연결하지 않았다.

현재 이 문서는 **연애 사주** 엔진을 설명한다. 메인·정통·MBTI 분리는 [콘텐츠 구조](CONTENT_ARCHITECTURE.md)를 참고한다.

## 처리 구조

`입력 검증 → 기존 한국 달력/절기 계산 → 구조화된 사주 특징 → 관계 주제별 규칙 선택 → 무료/상세 문안과 표시 근거 → 응답`

로컬 개발은 계산 결과를 서버 메모리에 임시 보관하고, 공개 무료 체험은 요청마다 재계산해 반환하며 보관하지 않는다.

| 계층 | 위치 | 역할 |
| --- | --- | --- |
| 원국 계산 | `web/src/lib/saju.ts` | 한국 음력·KST·자정 일주 변경 정책으로 네 기둥 확정 |
| 구조화된 특징 | `web/src/lib/saju-analysis.ts` | 확정된 기둥에서 음양·십성·지장간·월지 계절·육합/충 추출 |
| 관계 규칙 | `web/src/features/relationship/server/interpretation.ts` | 장별 단서 선택, 적용 조건·편집 문안·예외 정의 |
| 리포트 구성 | `web/src/features/relationship/server/report.ts` | 사주 단서, 직접 선택한 MBTI, 관심 장면을 구분해 조합 |
| 읽기 근거 | `web/src/features/reading/ExplanationBasis.tsx` | 각 장의 접힌 ‘이렇게 읽은 이유’ 영역 |

## 계산으로 구하는 범위

- 일간의 천간·음양·오행, 각 기둥 천간의 십성, 각 지지의 지장간과 십성.
- 십성은 일간과 대상 천간 사이의 오행 관계 및 음양으로 계산한다. 라이브러리의 `七杀`는 화면에서 `편관`으로 표기한다.
- 지장간은 목록이며 가중치·세력 점수로 합산하지 않는다. 표의 첫 지장간을 대표 질문에 쓰는 것은 아래의 편집 선택이다.
- 월지 `寅卯/巳午/申酉/亥子`는 봄/여름/가을/겨울, `辰戌丑未`는 ‘계절 전환’으로 표시하는 V1 구분이다. 월령의 세부 강약이나 기후 영향 판정이 아니다.
- 육합 6쌍과 육충 6쌍의 존재만 검출한다. 합화·형·해·삼합·반합·대운·세운·신강·용신은 이번 범위가 아니다.
- 기존 원국의 확정값만 읽는다. 출생시간 미상은 시주 특징·관계를 제외하고, 절기 경계에서 년주/월주가 미확정이면 관련 특징·계절도 제외한다. 새 모듈이 별도로 날짜를 재계산하지 않는다.

십성·지장간·지지 쌍은 설치된 `lunar-typescript@1.8.6`의 `LunarUtil` 표와 대조한다. 출처: [저자 저장소의 LunarUtil](https://github.com/6tail/lunar-typescript/blob/master/src/lib/LunarUtil.ts), [EightChar](https://github.com/6tail/lunar-typescript/blob/master/src/lib/EightChar.ts). 이 대조는 명리 분류표 구현의 일치 검사이며 성격·미래 예측의 검증을 의미하지 않는다.

## 해석 규칙과 선택 순서

문안은 이 프로젝트에서 작성한 자기성찰용 초안이다. 전통 분류를 관계의 질문으로 연결하는 방식은 아직 전문가가 검수하지 않았다. 적용 조건과 예외는 코드의 `RULE_CATALOG` 및 각 결과의 서버 내부 `audit.rules`에 남는다.

| 장 | 사용한 단서 | 선택·예외 |
| --- | --- | --- |
| 첫 요약 | 일간 음양·오행, 속도와 표현 장에서 고른 주제 | 사용자가 고른 관심 장면은 자기보고 입력으로 따로 표시 |
| 가까워지는 속도 | 월지 계절, 월지 첫 지장간의 십성 | 월주 미확정이면 일지 첫 지장간으로 대체하고 계절 설명 생략 |
| 마음을 전하는 방법 | 일간 제외 천간 십성의 두 계열 공존 | 코드 `PAIRS`의 첫 일치 조합 선택. 계열별 근거는 월간→년간→시간 순. 두 계열 미선택 시 첫 확정 천간, 모두 미확정이면 일지 첫 지장간. 예시 대사는 월간→년간→시간의 첫 확정 천간에서 별도 선택하고 그 근거도 표시 |
| 좋아하는데 자꾸 어긋나는 순간 | 지지의 육합·충 | 종류별로 일지를 포함한 쌍 우선, 없으면 전체 년·월·일·시 순의 첫 쌍. 합과 충이 함께 있으면 두 단서를 함께 사용. 모두 없으면 일지 첫 지장간 질문 |
| 나에게 맞는 사랑의 방식 | 사용자가 고른 관심 장면과 해당 장의 단서 | 관심 미선택 시 속도 장에서 고른 주제의 행동 과제 사용 |

십성 계열 `비겁/식상/재성/관성/인성`은 코드에서 `self/output/care/standard/reflection`이라는 편집용 태그로 묶는다. 이 영문 태그가 표준 심리 분류라는 뜻은 아니다. 선택 순서나 첫 지장간은 ‘가장 강한 성향’이라는 판정이 아니며, 성별·닉네임으로 해석을 바꾸지 않는다.

MBTI를 입력하지 않으면 해당 비교와 근거를 만들지 않는다. 입력한 경우에도 사주와 합산 점수나 새 유형을 계산하지 않는다. 관심 장면은 이제 서버 입력 `focus`로 전달되어 도입 질문, 해당 상세 장의 상황, 마지막 실천 과제에 사용한다. 사주 계산값은 관심 장면에 따라 바뀌지 않는다.

## 표시 근거와 내부 기록

- 각 장의 `evidence`는 `chart / mbti / focus`를 구분한다. 화면에는 자연어 라벨과 실제 사용한 값만 표시한다.
- 내부 `audit`는 버전·`editorial-draft` 상태·전체 특징·section별 적용 규칙과 조건을 담는다. 문장에 필요한 사주 규칙, MBTI, 관심 선택 조건을 각각 기록한다.
- 미리보기 API는 기존 원국과 2개 장, 관심 선택 등을 반환하며 상세 장과 전체 `audit`는 넣지 않는다. 공개 무료 체험의 별도 전체 읽기 API는 상세 장을 반환하지만 내부 `audit`는 보내지 않는다. 클라이언트 번들에서 해석 문안 모듈을 가져오지 않는다.
- 로컬 리포트와 감사 기록은 서버 메모리에 최대 1시간 보관하며 규칙 버전이 바뀌면 재생성이 필요하다. `SAJU_PUBLIC_DEMO=1` 공개 무료 체험은 요청마다 현재 규칙으로 재계산하고 앱 DB·서버 Map·쿠키에 입력·리포트를 보관하지 않는다. 두 모드 모두 외부 AI나 광고 도구로 전달하지 않는다. [배포 문서](DEPLOYMENT.md) 참고.

## 고정 검수 사례

| 입력 비교 | 기술적으로 확인할 기준 |
| --- | --- |
| 2000-03-07 12:00 / 2000-05-06 12:00, INFP | 년주·일주·시주가 같고 월주만 己卯/辛巳. 제목만 아니라 관련 상세 문단과 근거가 달라짐 |
| 2000-01-07 12:00 / 21:00, INFP | 년·월·일 유지, 庚午/乙亥 시주 차이가 해당 문단과 근거에 반영됨 |
| 2000-01-07, 시간 미상 | 시주·시주 지장간·시주 관련 쌍 없음 |
| 2024-02-04, 시간 미상 | 년·월·시주와 계절을 추정하지 않음 |
| 2024-02-04 17:26 / 17:28 | 기존 KST 입춘 경계와 특징 분석이 일치 |
| 같은 입력에서 관심 장면만 변경 | 특징은 같고 실천 과제는 달라짐 |
| 같은 입력에서 성별·별명 변경 | 사주 해설 동일 |
| MBTI 없음 | 유형 추정·MBTI 근거 없음 |
| 일지의 합 + 다른 기둥의 충, 반대 배치 | 두 종류를 빠뜨리지 않고 함께 해설 |

자동 검사는 구현의 일관성·근거 연결을 확인한다. 전문 만세력 교차 검증, 문안의 명리 타당성, 실제 독자의 이해도·중복·만족도 검증을 대신하지 않는다.

## 다음 품질 단계

1. 전문가에게 위 계산 정책·표·규칙 선택 순서·고정 사례를 함께 전달해 수정 의견을 기록한다. 검수 통과 규칙만 별도 상태로 전환한다.
2. 시범 독자에게 근거가 납득되는지, 여러 장이 반복되는지, 실제 사용할 문장이 있는지 확인한다.
3. 기준 사례와 장별 구성을 고정한 뒤 AI에는 검수된 특징·선택 규칙·근거·주제를 전달한다. 원국 재계산이나 없는 단서 추가는 맡기지 않고, 생성 실패 시 검수 문안으로 대체한다.
4. 자료가 늘어나면 검수된 문서의 검색을 붙인다. RAG·자체 모델 도입은 이 기준 사례보다 품질이 개선되는지 확인한 뒤 결정한다.

## 0.3 서사 확장

10일간 전용 이미지와 십성별 장면·대사를 추가했다. `lead`와 소제목이 있는 `sections`를 화면에 렌더링하고 동일 본문을 `body`로 합친다. 첫 장의 일지 지장간과 마지막 장의 관계 방식·실천·대사도 별도 근거로 기록한다. 연애 상품은 MBTI를 입력받지 않으며 비교 상품의 네 축 해설은 별도 엔진으로 분리했다.
